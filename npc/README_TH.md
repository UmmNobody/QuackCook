# QuackCook — ส่วนงาน NPC

ตำแหน่งในเกมหลัก: `D:\ClassGame\QuackCook\npc`

ทุกไฟล์ในโฟลเดอร์นี้เป็นส่วน NPC ที่เพิ่มใหม่ ไม่แก้ `project.godot`, `scene/main.tscn`, Player, ระบบทำอาหาร หรือถาดพักอาหารของทีม ไม่มี Web export และไม่มีการอัปโหลด itch.io

## เปิดดูงาน

1. เปิดโปรเจกต์ `D:\ClassGame\QuackCook\project.godot` ใน Godot 4.7
2. เปิด `res://npc/tests/npc_test.tscn`
3. กด **F6 — Run Current Scene** เพื่อเข้าห้องตรวจ NPC (F5 ยังเปิดฉากหลักเดิมของทีม)
4. กด **Play full sequence** หรือเลือกแต่ละท่าจากรายการ

ตัวกลางคือ Prisoner, ด้านข้างเป็นตำรวจที่เต้นคนละคลิป, แถวหลังแสดงหัวโล้น / ผมทอง / ผมดำ / ผมน้ำตาล / ผ้าปิดตา / หมวก ทั้งหมดใช้ Prisoner scene เดียวกัน

ปุ่ม Receive tray รับถาดใหม่, Throw tray > fight mode โยนถาดแล้วตั้งการ์ด, Walk to marker ทดสอบการเดินจริง, Police: swap both dances สลับท่าตำรวจ และ Show 4 empty slot markers แสดงหมายเลขช่องวางของโดยไม่สร้างอาหาร

คลิกขวาค้างลากเพื่อหมุนกล้อง ล้อเมาส์ซูม Space หยุด/เล่น Prisoner และ R รีเซ็ต การเลือกคลิปเดี่ยวจะหยุดที่เฟรมสุดท้ายถ้าไม่ใช่ Loop ส่วน Timeline ใช้ตรวจ pose; เลื่อนท่าโยนข้ามเฟรม 18 จะปล่อยถาดให้ตกด้วยฟิสิกส์ เลื่อนกลับก่อนเฟรม 18 จะจับถาดชิ้นเดิมคืน เมื่อ Resume ท่าโยนหลังเลื่อน Timeline จะเริ่มท่านั้นใหม่เพื่อทดสอบตั้งแต่ต้น

## โมเดลและแอนิเมชัน

ความเร็วเล่นใน Godot เป็น **1.75×** (เร็วขึ้น 100%) รวมท่าเต้นตำรวจ ยกเว้นทุกคลิปที่ชื่อมี `Walk` และ `P1_Boxing_Flurry` ที่คง **1.0×** จังหวะจับ/ปล่อยถาดและโจมตียังคงอยู่ที่เฟรมเดิม จึงเกิดเร็วขึ้นตามคลิป โดยฟิสิกส์หลังปล่อยถาดใช้ความเร็วปกติของเกม จำนวนเฟรมใน Blender/GLB ไม่เปลี่ยน ตัวเลขความเร็วปัจจุบันแสดงในห้องทดสอบ

- `assets/prisoner.glb`: Prisoner ต้นแบบเดียว, กระดูก 8 ชิ้น, 13 แอนิเมชันเดิม, มือแบ/กำปั้น และอุปกรณ์ศีรษะ 5 ชุด
- `assets/police.glb`: Police, กระดูก 8 ชิ้น, `Police_Dance_01` (แมวโยกตัวและมือระดับอก) กับ `Police_Dance_02` (โยกข้างและสลับยกมือจาก GIF จิ้งจก) เป็นการปรับท่าจากภาพอ้างอิงให้เหมาะกับทรงเป็ด ไม่ใช่ motion capture
- `assets/serving_tray.glb`: ถาดเสิร์ฟแยก 4 ช่อง ไม่มี armature และไม่มีโมเดลอาหาร
- ทุกส่วนของตัวละคร/อุปกรณ์ใช้ Shade Smooth โดยรักษาขอบคมที่มุม 55 องศา และส่งออก normals ไปกับ GLB
- ไม่มี `tray_anchor` ในโครงกระดูกและแทร็กแอนิเมชันแล้ว จุดจับถาดคำนวณจาก `hand.L` + offset ที่ตรวจเทียบกับท่าถือเดิม
- รูปลักษณ์สุ่มครั้งเดียวตอน spawn สามารถกำหนด `appearance` ใน Inspector ได้: -1 สุ่ม, 0 โล้น, 1 ทอง, 2 ดำ, 3 น้ำตาล, 4 ผ้าปิดตา, 5 หมวก
- ชุดที่เดิมชื่อ WHITE มีเฉพาะผ้าปิดตา จึงใช้ผ้าปิดตาตามต้นฉบับตามที่ตกลง ไม่ได้สร้างผมสีขาวเพิ่ม

## ใช้ต่อในฉากเกม

ลาก `scenes/prisoner.tscn`, `scenes/police.tscn` หรือ `scenes/npc_world.tscn` ลงในฉากที่รับผิดชอบ แล้วปรับตำแหน่งให้เท้าอยู่ระดับพื้น โมเดลหันหน้า +Z

ตัวอย่าง API สำหรับโค้ดระบบเกมที่จะเขียนเชื่อมภายหลัง:

```gdscript
# เดินไปยังตำแหน่งคิว/เคาน์เตอร์/ทางออกที่ระบบเกมกำหนด
npc.walk_to(counter_position)

# รับถาด NPC ใหม่ หรือส่ง existing_tray เพื่อใช้ถาด instance ที่มีอยู่
npc.pickup_tray()

# ใส่ Node3D ของอาหารลงช่องว่าง: คืน false ถ้าเต็มหรืออาหารซ้ำ
# ผู้เรียกต้องจัดการ ownership ของอาหารจากระบบเดิมก่อนส่งเข้าถาด
var accepted: bool = npc.receive_food(food_node)

# เริ่มสู้: มีถาดจะโยนก่อน แล้วเดินเข้าหาเป้าหมายและเล่นท่าโจมตีเมื่อใกล้
npc.begin_combat(target_node)

# ยกเลิกเป้าหมาย กลับโหมดตัวเปล่า
npc.end_combat()

# ระบุการโจมตีแบบยืนเองได้
npc.request_attack("P1_Kick_Front_R")
```

Signals ที่ให้ระบบเกมเชื่อม: `arrived`, `tray_filled`, `tray_released`, `animation_completed`, `attack_contact`

`attack_contact` แจ้งจังหวะหมัด/เท้าเท่านั้น **ยังไม่หัก HP หรือเพิ่ม hitbox ให้ผู้เล่น** ระบบเกมต้องตรวจระยะ/การโดนและคำนวณดาเมจเอง ถาดพักอาหารเดิมและระบบสูตรอาหารไม่ได้เชื่อมกับถาด NPC อัตโนมัติ

`walk_to` ค่าเริ่มต้นใช้เดินตรงบนพื้นที่โล่งพร้อมชนวัตถุ เหมาะกับห้องตรวจนี้ ถ้าเกมมีสิ่งกีดขวางหรือทางเดินซับซ้อน ให้ทีมเพิ่ม/bake `NavigationRegion3D` ในฉากของตน แล้วเปิด `use_navigation` ของ NPC สคริปต์จะใช้ NavigationAgent3D ที่เตรียมไว้ ไม่แก้ navigation หรือผังฉากของทีมโดยอัตโนมัติ ระบบจัดคิวและเงื่อนไขว่าทำไม NPC เริ่มโกรธยังเป็นหน้าที่ระบบเกม

## ถาดและของ 4 ช่อง

`pickup_tray` freeze ถาดระหว่างถือ, frame 18 ของท่ารับเริ่มตามมือ, frame 18 ของท่าโยนยกเลิกการติดตามมือและเปิดฟิสิกส์พร้อมความเร็วเริ่มต้น ถาดชิ้นเดิมรวมถึง Node ลูกในทั้ง 4 ช่องอยู่ต่อหลังโยน

`insert_item(item, index)` ใช้ index 0–3 หรือ -1 เพื่อหาช่องว่าง ของที่เป็น RigidBody3D จะหยุดฟิสิกส์/การชนของตนระหว่างติดถาด เมื่อ `remove_item(index)` จะคืนค่าฟิสิกส์เดิม อาหารยังไม่กระเด็นแยกจากถาด และยังไม่ได้ปั้นโมเดลอาหาร

## การนำเข้าและแก้แอนิเมชัน

ไฟล์ `.glb.import` ตั้ง 24 fps ปิด Optimizer และเก็บ RESET เพื่อรักษาจังหวะเดิม ควรเก็บไฟล์ import กับ `npc_import.gd` ไปพร้อม assets อย่าเปลี่ยนพาธโฟลเดอร์ `npc` โดยไม่แก้ `res://npc/…` ในสคริปต์

ไฟล์ Blender ที่แก้คือ `Prisoner_1_Walk_Blockout.blend` เดิมใน outputs ของงานนี้ มีฉาก `03 Prisoner 1 - ANIMATION PREVIEW` และ `04 Police - DANCE PREVIEW` เลือก rig แล้วเปลี่ยน Action ใน Action Editor ได้ ท่าเต้น 01 วนเฟรม 1–48, ท่า 02 วนเฟรม 1–96 (มีเฟรมปิดลูป 49/97 สำหรับ export)

แก้ Blender แล้วต้อง export GLB ใหม่จึงจะเห็นการเปลี่ยนใน Godot; การบันทึก .blend อย่างเดียวไม่แก้ GLB อัตโนมัติ สำเนาก่อนแก้เก็บอยู่ใน work ของงาน Codex

## ผลตรวจ

ผลอัตโนมัติอยู่ที่ `tests/validation_report.json` ตรวจ 13 คลิป Prisoner, 2 คลิป Police, ไม่มีกระดูกถาด, รูปลักษณ์แต่ละ instance อิสระ, จุดกระดูกเทียบ Blender, รอยต่อท่าเต้น, มือแสดงตรงเฟรม, ของ 4 ช่องและขอบเขตความจุ, ถาดชิ้นเดิมหลังโยน, การชนพื้น, เดินถึงจุดหมาย และโจมตีอยู่กับที่

เพิ่มการตรวจ Mesh หลัง skin 783 ชุดเทียบกับ Blender และเทียบทั้งตำแหน่งกับมุมถาดช่วงที่ถือ ส่วน `tests/validate_npc_ui.gd` ตรวจปุ่ม Receive/Throw, การ Pause ก่อนโยน, Timeline ข้ามจุดปล่อยทั้งไปและกลับ และ Play full sequence ผลอยู่ที่ `tests/ui_validation_report.json`

รันซ้ำด้วย `godot --headless --path D:/ClassGame/QuackCook --script res://npc/tests/validate_npc.gd` โดยใช้พาธ Godot executable บนเครื่อง ไม่มีการ build เว็บในขั้นนี้
