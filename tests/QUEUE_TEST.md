# Queue test

เปิด `scenes/Queuetest.tscn` แล้วกด F6 เพื่อทดลองคิวด้วยโมเดล `asset/model/prisoner.glb`

## ควบคุม

- V: สลับมุมมองรวมกับ FPS
- 1 / 2 / 3 / 4: เสิร์ฟไก่ / ผัก / ข้าว / น้ำ หรือคลิกปุ่มบนหน้าจอในมุมมองรวม
- ใน FPS ใช้ WASD และเมาส์ เล็งปุ่ม SERVE บนโต๊ะแล้วคลิกซ้าย
- คลิกหยิบของบนโต๊ะอุปกรณ์ข้างผู้เล่น กดคลิกซ้ายค้างแล้วปล่อยเพื่อโยนใส่นักโทษ กด Q เพื่อปล่อยแบบไม่สร้างดาเมจ
- นักโทษที่เลือดหมดล้มเป็น Ragdoll เล็งร่างให้มี Outline แล้วคลิกหยิบ ใช้ปุ่มโยนเดิมได้ หรือถือไปคลิกถังขยะทางขวาของผู้เล่น
- N: เริ่มเวฟใหม่ตาม Test Wave Size เมื่อเวฟก่อนออกจากฉากหมดแล้ว
- P: พัก/เล่นต่อการสร้างนักโทษที่เหลือในเวฟ (ตัวที่เกิดแล้วเดินต่อ)
- F: เติมอาหารทุกหลุมให้เต็มสำหรับทดสอบ
- R: ยกเลิกเวฟ รีเซ็ตนักโทษ ลำดับคิว และอาหาร แล้วเริ่มเวฟทดลองใหม่
- Esc: ออกจากฉากทดสอบ

ป้ายบนหัวใช้ C = ไก่, V = ผัก, R = ข้าว, W = น้ำ รายการที่ได้รับแล้วจะหายจากป้าย
นักโทษใช้ชุดจากโมเดลจริง ป้ายชื่อเป็นสีเขียวเมื่อได้รับครบ และสีแดงเมื่อโกรธ

## ตัวอย่างทดลอง

สองคนแรกใช้รายการตัวอย่างของงาน เมื่อ Use Example Orders เปิดอยู่:

1. คนแรกต้องการไก่ ผัก น้ำ และหยุดที่ไก่
2. คนที่สองต้องการผัก ข้าว น้ำ แต่ยังเข้าช่องไก่ไม่ได้จนคนแรกขยับ
3. กด 1 ให้คนแรก เขาจะไปผัก และคนที่สองจะติดอยู่หน้าไก่
4. กด 1 อีกครั้งหลังคนที่สองยืนประจำช่องแล้ว จะทำให้คนที่สองโกรธ

คนถัดไปสุ่มชนิดอาหารไม่ซ้ำกัน ความอดทนลดเฉพาะตอนยืนในช่องเสิร์ฟและยังรับไม่ครบ
การเสิร์ฟผิดหรือซ้ำใช้หนึ่งหน่วยแล้วทำให้โกรธ; ช่องว่าง/คนกำลังเดิน/อาหารหมดไม่ใช้สต็อก
นักโทษโกรธเล่นท่าโยนถาดและเตรียมต่อสู้ก่อนเดินออกข้างคิว อ้อมโต๊ะ แล้วไล่ผู้เล่นและส่ง `attack_contact` ตามจังหวะหมัด/เตะในอนิเมชั่น
ฉากนี้แสดงจำนวน Hits เพื่อทดสอบ ยังไม่มีระบบ HP หรือความเสียหายของผู้เล่น
เส้นทางเดินคิวเป็นทางตรงระหว่าง Marker และทางอ้อมเป็นจุดที่จัดไว้สำหรับฉากนี้

## โครงสร้าง

ถาดนักโทษอยู่ที่ `scenes/serving_tray.tscn` ใช้ `asset/model/serving_tray.glb` และกล่องอาหาร 4 สีที่ซ่อนไว้ตอนเริ่ม
เมื่อนักโทษถึงจุดรับถาด จะเล่นท่ารับถาดประมาณ 1.96 วินาที (ปรับ `Tray Pickup Duration` ใน prisoner.tscn ได้) ถาดปรากฏช่วงจับที่ 55% และต้องรอจบท่าจึงเดินต่อ
ถาดเป็นลูกของ `TrayHoldPoint` ใน prisoner.tscn ตำแหน่งจุดนี้อัปเดตจากกระดูกมือทั้งสองตามอนิเมชั่น ปรับระยะชดเชยด้วย `Visuals > Tray Hand Offset`

ถาดที่ถือจะถูกลบพร้อมนักโทษเมื่อออกจากฉากหรือรีเซ็ต และแต่ละคนมีข้อมูลการแสดงอาหารเป็นของตัวเอง

ถาดที่ทิ้งหายหลัง 8 วินาที และถูกล้างเมื่อรีเซ็ต/ออกจากฉาก ปรับ `Tray Throw Forward Speed`, `Tray Throw Up Speed`, `Discarded Tray Lifetime` ที่ prisoner ได้

## เรียกเวฟจาก game loop

Spawner จะไม่เริ่มเองจนกว่าจะเรียกฟังก์ชัน หลังลงทะเบียน layout ของ QueueManager และกำหนด `actor_parent` แล้ว:

```gdscript
# วันแรก / วันถัดไป ให้ game loop เป็นคนเลือกจำนวน
var accepted: bool = $Spawner.start_wave(6)
# false เมื่อจำนวน <= 0, ยังมีเวฟเดิมอยู่ หรือยังตั้งค่าฉากไม่พร้อม
```

`start_wave(count)` เป็นการกำหนดจำนวนทั้งหมดของเวฟ ไม่ใช่จำนวนที่อยู่พร้อมกัน
คนแรกเกิดใน process ถัดไป จากนั้นทยอยเกิดตาม Spawn Interval ถ้าทางเข้าคิวเต็มหรือถึง Max Active Prisoners จะรอโดยไม่หักจำนวนคงเหลือ
เช่นเวฟ 20 คนและ Max Active Prisoners = 12 จะค่อย ๆ สร้างจนครบ 20 คน เมื่อมีคนออกจากฉากหรือหมดสติและทางเข้าคิวว่าง
ไม่มีสูตรเพิ่มคนรายวันและไม่มีการเริ่มวันถัดไปอัตโนมัติ

- `wave_started(total)`: รับคำสั่งเริ่มเวฟแล้ว
- `wave_spawn_finished(total)`: สร้างครบจำนวนแล้ว แต่ยังมีนักโทษในฉากได้
- `wave_completed(total)`: สร้างครบและนักโทษของเวฟออกจาก scene tree หมดแล้ว
- `wave_total`, `wave_spawned`, `remaining_to_spawn()`, `wave_alive_count()`, `wave_active`: อ่านสถานะของเวฟ โดย wave_alive_count นับเฉพาะคนที่ยังมีสติ
- `wave_pending_count()`: จำนวนคนของเวฟที่ยังอยู่ในฉาก รวมร่างหมดสติที่ยังไม่ทิ้ง
- `spawning_paused`: พักเฉพาะการสร้างอัตโนมัติ; เริ่มเวฟใหม่จะคงค่าพักไว้
- `spawn_one(order_override)`: ขยับการสร้างหนึ่งคนสำหรับทดสอบ แม้พักอยู่ แต่ต้องมีเวฟและโควตาเหลือ
- `cancel_wave()`: ยกเลิกจำนวนที่ยังไม่เกิดและการติดตามเวฟ ไม่ลบนักโทษเดิมและไม่ส่ง signal สำเร็จ

หากต้องการรีเซ็ตทั้งหมด ให้เรียก `cancel_wave()` ก่อน `QueueManager.reset_queue()` แล้วจึง `start_wave(...)`
นักโทษที่โกรธยังนับเพดานในฉาก ส่วนคนหมดสติถูกปลดจากคิวและเพดานทันที แต่ยังขวางการจบเวฟจนกว่าจะถูกหยิบไปทิ้งถังขยะ
ฉาก Queuetest เรียกเวฟ 6 คนเองตอนเริ่มเพื่อทดลอง ปิด Start Test Wave On Ready ได้

## ดาเมจจากของที่โยนและการหมดสติ

ทุกวัตถุที่โยนผ่าน Player/Head รวมร่างนักโทษ ใช้สูตร `linear_velocity.length() × Throw Damage Per Speed` ค่าตัวคูณเริ่มต้น 2 ดาเมจต่อ m/s ไม่มีตัวคูณชนิดวัตถุหรือน้ำหนักเพิ่มเติม
บันทึก linear velocity ของแต่ละวัตถุ/กระดูกทุก physics frame แล้วใช้ค่าจากเฟรมก่อนการชน เพื่อหลีกเลี่ยงการอ่านค่าหลังฟิสิกส์หยุดหรือสะท้อนวัตถุแล้ว เก็บค่าพร้อมเหตุการณ์ชนก่อนส่งดาเมจแบบ deferred
การชะลอตัวและการเด้งระหว่างทางจึงเปลี่ยนดาเมจตามความเร็วจริงใกล้จุดกระแทก ไม่ใช้แรงชาร์จตอนปล่อยเป็นดาเมจตลอดวิถี ความเร็วเชิงมุมไม่ถูกนำมาคำนวณดาเมจ
หนึ่งครั้งที่โยนทำดาเมจต่อนักโทษแต่ละคนได้ครั้งเดียว แต่โดนหลายคนได้ การเด้งชนพื้น/โต๊ะไม่ปิดดาเมจทันที
เมื่อหยิบกลับมาจะยกเลิกการโยนเดิม และเริ่มสิทธิ์ใหม่เมื่อโยนอีกครั้ง เมื่อวัตถุหยุดเคลื่อนที่/หมุนต่อเนื่อง 0.75 วินาทีจะหมดสิทธิ์สร้างดาเมจ
การถือเดินชน กด Q ปล่อย หรือถาดที่นักโทษโยนทิ้งเองไม่เปิดสิทธิ์นี้ ร่างที่หมดสติไม่รับดาเมจซ้ำ

คนที่ยังไม่โกรธเมื่อโดนดาเมจแล้วเลือดเหลือจะโกรธและออกมาต่อสู้ ถ้าเลือดหมดจะข้ามท่าโกรธและหมดสติทันที หยุดอนิเมชั่น/เดิน/โจมตี/รับอาหาร และปล่อยถาดที่ยังถืออยู่
เมื่อได้รับดาเมจ โมเดลจะกระพริบแดงอ่อน 2 จังหวะประมาณ 0.31 วินาที พร้อม Tween ยุบตัวเล็กน้อยแล้วเด้งคืนใน 0.28 วินาที ใช้ material ของแต่ละคนแยกกัน และไม่ขยาย CharacterBody/Collider
โดนซ้ำระหว่างเอฟเฟกต์จะเริ่มเอฟเฟกต์ใหม่และคืนสี/ขนาดเดิมเมื่อจบ ถ้าเป็นการโดนจนหมดสติจะคืนสเกลทันทีและใช้เฉพาะกระพริบสี เพื่อไม่เปลี่ยนสเกลของ Skeleton ขณะที่ Ragdoll เริ่มจำลองฟิสิกส์
Ragdoll ใช้ PhysicalBoneSimulator3D กับลำตัว หัว มือ 2 ข้าง และเท้า 2 ข้างของ Skeleton เดิม จึงเก็บตัวเลือกผมและตัวตนในเวฟไว้
ตอนหยิบจะพักฟิสิกส์และรักษาท่าล้มเดิม แล้วเคลื่อนทั้งร่างตามจุดถือ เมื่อปล่อยจะเริ่มฟิสิกส์จากตำแหน่งที่ถือโดยไม่กลับไปจุดเกิด
กระดูกทุกชิ้นส่งการชนผ่าน ThrowImpact ตัวเดียวของร่าง ใช้ความเร็วเชิงเส้นของกระดูกที่ชน และยังหักเลือดได้เพียงครั้งเดียวต่อเป้าหมายในการโยนเดียวกัน
ร่างไม่ฟื้นและไม่หายตามเวลา ต้องถือแล้วคลิกถังขยะ หรือใช้ R รีเซ็ตในฉากทดสอบ ถังขยะยังรองรับวัตถุดิบและการล้างอาหารในภาชนะตามเดิม
HUD แยก Alive (คนที่มีสติ) กับ Bodies (ร่างที่รอเก็บ) เวฟจบเมื่อสร้างครบ คนปกติออกหมด และร่างทั้งหมดถูกทิ้งแล้ว
GameManager ยังเป็นโครงเปล่าที่ผู้ใช้สร้างไว้ การจัดวัน/สูตรเพิ่มคนยังไม่ได้เพิ่มในงานนี้
